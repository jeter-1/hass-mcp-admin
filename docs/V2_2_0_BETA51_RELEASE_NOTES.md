# Engineering 2.2.0-beta.51 release notes

Beta 51 materializes the replay-backed production-path agreement correction for
HAMCP-089 in the unmerged source pull request. The published and deployed
release remains Beta 50 until separately authorized protected merge and
publication. Stable v1.1.2 and the 51-tool Engineering catalog are unchanged.

## Replay-backed helper dependency evidence

A sanitized five-configuration Beta 50 replay now exercises the shipped direct
Home Assistant dependency provider, immutable dependency index and governance
planning path. The baseline retained 28 unrelated target-capable obligations
and five downstream profiles. The corrected standard-helper result is complete,
low/`standard_admin` and actionable with zero exact target dependencies, zero
target-relevant opacity and zero downstream profiles.

Finite State, fixed-trigger, literal-label, closed-domain and bounded dataflow
provenance now survives collection and attribute transport until target scope is
terminally resolved. Exact `states[key]` access and expression-only variable
actions preserve complete finite candidates. Complete conditional branches
retain their union. Unrelated target evidence is eliminated before consequence,
completeness, policy, actionability, fingerprint or lock aggregation.

Rendering one State through string concatenation now accounts for the State
relationship exactly once, without globally deduplicating distinct reads. The
rendered result remains scalar-tainted and becomes conservative if later reused
as an entity selector without independently proven finite identity.

Current, non-invalidated dependency snapshots may be reused for immediately
following plans. Every plan binds the exact generation, fingerprint and source
epoch it used, and freshness/invalidation races force a refresh. Final-preflight
fencing remains required before dispatch.

Unknown or caller-supplied selectors, incomplete labels, arbitrary filter/call
results, malformed or statement-prefixed templates, incomplete branches,
imports and bounded-processing failures remain opaque or coverage-failed. The
consequential control retains seven exact safety-critical profiles and remains
high/`elevated_admin` but actionable; arbitrary selectors remain incomplete,
non-actionable and conservatively locked.

New plans use `helper-dependency-risk-v10`. Persisted v3-v9 plans stay readable
with their historical evidence but require replanning and cannot authorize
current approval or execution.

## Compatibility and release boundary

No Jinja template rendering or execution was introduced. Public MCP schemas,
tool registration, provider admission and routing, fallback, write authority,
approval authority, task schema, workflows, containers, deployment behavior and
stable v1 are unchanged. Release materialization changes only the three
authoritative Engineering version declarations and consumes the staged
declaration.

HAMCP-089 is not accepted by source materialization. Post-deployment artifact
identity and two planning-only controls must pass under separate authorization
before a separately authorized reversible helper canary may be considered. This
task performs no merge, publication, promotion, deployment, live access,
approval, apply, dispatch or Home Assistant mutation.
