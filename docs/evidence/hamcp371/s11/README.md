## Disclosures

- **Search `name` equals `friendly_name` in every receipt.** The plan asks
  for `name` "equal to the seeded composed name". The lane seeded entities
  with no device, so the composed name the component reports is the entity
  name, which equals `friendly_name` on all six B occurrences (`r25-search`,
  `v25-search-text`). A composed name that differs from `friendly_name` is
  unobserved; the test asserts the value passes unchanged.
- **Overview entity-row `name` is synthetic.** Upstream writes it only when
  the composed name differs from `friendly_name`
  (`tools/smart_search/_overview.py:361-363`). No seeded entity met that, and
  the receipts' entity lists are empty, so this occurrence is unobserved until
  SR. `name` is observed on other overview rows.
- **Flat key model.** Names are admitted per read, not per path, so `current`
  and `latest` are admitted anywhere in the overview, not only inside
  `ha_mcp_update`.
- **Health differs from the plan text.** The plan's S11 section says the
  health injection raises `fields_dropped_by_policy` by two with
  `fields_withheld` unchanged. Health is a closed rebuild
  (`upstream_reads_9_2_platform.project`), in which `fields_dropped_by_policy`
  is always 0 and every unknown name is withheld and counted. The test asserts
  what the plan's ruling table row 2d says ("raises the count"): the client
  result is unchanged and `fields_withheld` rises.
