## Corrected evidence boundary

The dependency provider now records bounded completion independently for each
literal label selector. Home Assistant Core 2026.7.2, 2026.8.0 and 2026.8.1
all perform exact label-ID lookup first, then normalized-name lookup using
exactly `name.casefold().replace(" ", "")`. Beta 52 follows that contract.
An exact ID match is not unioned with another label's matching display name.

A canonical bounded entity-registry record with a complete label collection
that does not contain the resolved label proves that record is not a member;
an unrelated malformed entity identity with such a complete nonmatching
collection can no longer poison every selector. A malformed potential member,
unreadable label collection, duplicate relevant entity identity, incomplete or
unavailable inventory, missing lookup under incomplete label evidence,
conflicting label identity, membership overflow or selector overflow remains
explicitly incomplete. No malformed or clipped prefix can prove target
exclusion.

proven finite candidates. It preserves finite list, mapping, conditional,
loop, reviewed-filter, State-projection and `expand()` transport. A complete
set containing the target remains an exact dependency; a complete set omitting
the target becomes a terminal target exclusion; dependency-neutral operations
remain neutral. Mixed exact inclusion and incomplete provenance retains both
the exact relationship and conservative evidence. Dynamic labels,
caller-supplied selectors, imported or unknown contracts, malformed/cyclic
expansion and processing or coverage failure remain fail-closed.

The selector completion map, resolved label identity, complete membership
fingerprint, target disposition, dependency snapshot generation/fingerprint/
