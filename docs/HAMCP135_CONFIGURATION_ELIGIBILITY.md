# HAMCP-135 bounded configuration eligibility

An exact retry-removal script update, or the reviewed five-object caller-owned
retry composition, can now receive one authenticated owner plan approval through
the existing configuration route. High and safety-critical consequence evidence
remains visible. This grants configuration-write eligibility only; it does not
invoke a script, cover, automation or physical service.

## Proof and authority

`governance/configuration_eligibility.py` recognizes a closed structural grammar
from complete before/after bodies. It never evaluates Jinja or imports test
fixtures. Resource identities and notification recipient are parameters. Roles
are structural: one shared script, then Notification, Cleaner, Away and Bedtime;
Cleaner has two mutually exclusive sites. The exact order and previous-member
dependency are required. Mode, retained fields/actions, targets, parameters,
native predicates and durations, response reset/recognition and terminal paths
are checked, not inferred from action counts. Literal new report prose and a
literal description may vary; new report services/targets and behavior may not.

The minimal class preserves its unconditional first close, event wait and
successful branch. Only its retry/reporting region is replaced. It is not the
full retry contract. The complete composition requires all 11 positive guards:
exact-open before closing, full native caller policy before each first call,
and exact timeout result plus fresh full policy before each second call.
A missing, false, unavailable, malformed or erroring prerequisite cannot select
a call branch. Every refusing path terminates.

Traversal is bounded to 16,000 nodes, depth 40 and 400,000 UTF-8 string bytes per
before/after pair. Unsupported/exhausted proof grants no new eligibility. Exact
resource validation, complete semantic review projection and existing bounds
remain additional requirements. Templates are accepted only as exact prescribed
state-wait/result expressions in changed execution regions.

The server derives `configuration-retry-transfer-v1` proof, member hashes,
site/policy bindings and a digest after preparing the entire operation set.
Each operation binds this evidence through existing risk, policy subject,
semantic projection, plan and F3 preparation hashes. Complete proof is recomputed
on policy integrity checks and F3 execution. A marker alone is insufficient.
Unmarked historical plans retain their former policy and hashes; no approval or
prohibited plan is upgraded retroactively. Existing exact automation authority
remains unchanged. No new public schema, provider, adapter capability, storage
format, normalizer relaxation or client eligibility override is introduced.

## Execution and verification

This class requires active F3 execution. An absent F3 runtime refuses before
creating a legacy task, consuming approval or accessing the configuration writer.

Under the existing complete sequence lock union, the first child reads every
baseline. Before later children, prior verified members must match their expected
new fingerprints and unstarted members their baselines. The current child's
existing validation, comparison and final stale check still follow. Local refusal
is a child preflight outcome, not a global persistence fault. Approval consumption,
Core/provider authority, durable intent, one dispatch and readback-only recovery
remain owned by F3.

The final child's normal or recovery observation also reads the whole proposed
bundle. A separate `retry_bundle_current_verified` observation identifies this
check; mismatch prevents whole-task verified success while earlier child success
remains historical evidence. No durable success schema is added. Reads and writes
remain non-atomic against external writers. Stored configuration does not establish
reload completion, runtime generation or physical success.

## Behavior and recovery limits

The shared script stays single-mode, requests one close only for exact open,
waits for closed state for up to 30 seconds, and returns the exact
`hamcp135-garage-attempt-v1` dictionary. Only `open_after_timeout`/`returned`
permits retry consideration. Callers reset responses, use blocking calls and
recheck complete policy; each run permits at most two invocations, with no added
delay. Cleaner remains restart-mode; the others remain single-mode. Duration
checks remain full requirements. Reporting is per invocation and best effort.
There is no global attempt cap, atomic household safety interlock or guaranteed
wall-clock deadline.

Five writes are ordered S → N → C → A → B and are non-atomic. Old callers can
consume the new script without a response. New callers reject old/empty results.
Old in-flight runs and reload completion require separate operational evidence.
D2 remains a separate live-application gate. Script restoration remains outside
this forward proof. The separate [exact governed inverse contract](HAMCP135_GOVERNED_ROLLBACK.md)
binds a verified prefix of the full transfer and requires new elevated approval;
minimal-removal plans do not gain that authority. It discloses the restored retry
weakness and preserves explicitly partial caller-only outcomes. No inverse runs
automatically. The inverse retains its complete lock union across verified children
using exact fenced transfer. Independent review remains a separate gate; local
configuration verification is not household recovery.

positive use, guard preservation, exact member/dependency binding, every sequence
prefix, final-bundle drift, local refusal followed by unrelated success, lost
responses, duplicate execution and separately governed inverse creation. Existing risk/policy,
F3/readiness/storage/reverification regressions remain required.

Disposable Core 2026.9.4 acceptance uses separately sanitized bodies, synthetic

and actual waits/reloads. Its ignored harness, commands, output and immutable
image identity are delivered with implementation evidence. It is distinct from
source-derived probes and from live household acceptance. Release metadata,
publication, deployment, D2 and natural household observation remain separate.
