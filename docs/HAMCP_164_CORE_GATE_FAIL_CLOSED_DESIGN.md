## 2. Inventory

Every name that reaches the gateway falls into exactly one class:

- **mapped**: it has non-empty Core requirements. The gateway acquires them
  before the application and releases them afterwards (unchanged).
- **Core-independent**: an exact allowlist entry, or a conditional tool whose
  arguments select no Home Assistant call. The gateway passes it through without
  a Core lease (unchanged).
- **delegated**: currently published by the read gateway. The gateway passes
  it through; the read gateway acquires the delegated requirements (unchanged).
- **unmapped**: anything else. **Refused** (new).

## 3. Refusal semantics

When a Core runtime is installed (always, in production), the gateway refuses
an `unmapped` name **before** Core acquisition and **before** the MCP
application. The application owns every provider, upstream and Home Assistant
interaction, so no such call can occur.

The response is an MCP tool result (HTTP 200, `isError: false`, `success:
false`), matching the existing gateway Core refusals:

| Field | Value |
| --- | --- |
| `error` | `CoreRequirementUnmapped` |
| `error_code` | `unsupported_operation` (existing code; `R/errors.py` unchanged) |
| `retryable` | `false` |
| `details.reason`, `details.reason_code` | `core_requirement_unmapped` |
| `details.core_authority_acquired` | `false` |
| `details.provider_dispatch_occurred` | derived from request telemetry (`false`) |
| `details.upstream_attempted` | derived from request telemetry (`false`) |
| `details.home_assistant_request_count`, `details.upstream_request_count` | derived from request telemetry (`0`) |

The telemetry fields are read from the request's own counters, not hard-coded,
so they cannot claim an attempt that did not happen.

**Audit.** One record is written per refusal with `result_status=failure` and
`error_code=unsupported_operation`. Its `parameters` hold only:

- `core_route: unmapped` and `reason_code`;
- up to 32 argument **field names**, each bounded to 64 characters;
- `provider_dispatch_occurred: false` and `upstream_attempted: false`.

It has no argument values and no `resource_ids`.

**Gateway without a Core runtime.** A gateway composed with
`core_runtime=None` (tests and embedding only) enforces no Core gate at all:
not for mapped tools (unchanged) and not for unmapped ones. Production wiring
is pinned by `ProductionCompositionTests`, which builds `create_application`
and asserts `gateway._core_runtime is CORE_READMISSION`.

This is a deliberate choice. Applying the refusal without a runtime broke 10
existing harness tests that use synthetic names on a runtime-less gateway
(`test_mcp_inbound_security`, `test_mcp_sdk_compatibility`,
`test_hamcp188_mcp_sdk_session_contract`,
`test_rc2dev8_prevalidation_enforcement`) and added no production protection.

## 4. Closed allowlist

- `CORE_INDEPENDENT_STATIC_TOOLS` is a `MappingProxyType` and cannot be
  mutated at runtime.
- Membership is an exact `in` lookup. There is no prefix, wildcard,
  case-folding or whitespace normalization.
- `_validate_static_core_routes()` runs at import and raises `RuntimeError`
  when:
  - a requirement-map entry is empty (skip-on-empty cannot be restored through
    the map);
  - a name is both mapped and allowlisted, or allowlisted and conditional;
  - an allowlist name is empty or contains `*`, `?`, `[` or `]`;
  - a basis is unknown;
  - a justification is empty.
- Adding a tool to the allowlist requires a code change plus the pinned-table
  test update.

## 5. Decisions for Josh

1. **Prevalidation tools stay unmapped.** `call_service`, `delete_automation`,
   `reload_domain` and `upsert_automation` are refused by the prevalidation
   fence before the Core step, and the unmapped gate would refuse them again.
   So "every tool is mapped or allowlisted" reads, precisely, as "mapped,
   allowlisted, or pinned-refused". The table test pins all four.
2. **Runtime-only gate** (§3).
3. **Residual findings** (§8) are disclosed, not changed. Each needs either an
   unauthorized file or a change to degraded-Core behavior.

## 7. Telemetry truthfulness

The refusal returns before `self.app`. Request telemetry therefore records no
Home Assistant request, no upstream request and no provider dispatch, and the
response and audit record report exactly that. Metrics record a failed tool
call with `unsupported_operation`.
