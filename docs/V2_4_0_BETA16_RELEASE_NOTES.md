# Engineering 2.4.0-beta.16 release notes

Garage configuration eligibility is the only implementation increment in this
release. Preparation starts from protected beta.15 source
`740a4392d1aafa61e5d482a8ddc329d69c0b1839` and garage implementation
`bcc75d26f2e5b388c0c2599baffe8c6336fc0309`. Govee package administration and the
HAMCP-151 add-on restart correction are separate unreleased streams.

An exact minimal retry-removal script update, or the reviewed five-object
caller-owned retry composition, can become execution-eligible through the
existing governed configuration route. The server must prove the complete
before/after transformation using its bounded structural grammar. Unsupported,
incomplete, tampered or over-budget configurations gain no new eligibility.
High and safety-critical consequences remain visible; an authenticated external
owner approval is still required for the exact immutable plan. A historical
prohibited plan or approval is not upgraded by installing this release.

The full composition preserves all 11 positive consequential-call guards. Its
single-mode script issues one close only for exact open, waits for closed state
for up to 30 seconds and returns the prescribed response dictionary. Each caller
checks its full policy before the first invocation and considers one second
invocation only after the recognized timeout result and fresh policy checks.
Cleaner remains restart-mode; other callers remain single-mode. This is a budget
per caller run, not a global two-attempt limit or an atomic physical interlock.
The minimal transformation preserves its original unconditional first close and
has no structured response; it must not be described as the full design.

Marked plans require active F3, with no legacy-writer fallback. The existing lock
union protects Engineering execution while all baseline members, each verified
prefix and the final bundle are checked against their bound fingerprints.
Approval consumption, durable intent, dispatch ownership and readback-only
recovery remain enforced. Local stale-state refusal stays local to the plan.
Five configuration writes remain non-atomic, and external Home Assistant writers
are not locked out by Engineering's own locks. Saved configuration does not
prove reload completion, safe handling of in-flight runs or physical outcome.

The inverse that restores the original internally retrying script remains
prohibited. Eligible caller-only inverses are explicitly partial and require
fresh approval; no rollback or script restoration runs automatically. D2
operational recovery remains a separate prerequisite to household application.
See [the configuration contract](HAMCP135_CONFIGURATION_ELIGIBILITY.md).

The healthy catalog stays **83 = 58 native + 25 delegated**. All existing tool
descriptors, 21 compiled Core profiles, signed registry applicability, upstream
ha-mcp admission, dependencies, workflow permissions, durable formats and
stable v1.1.2 are preserved. No new tool, profile, signing requirement, direct
physical-action route or generic script eligibility exemption is introduced.
The exact Core 2026.9.4 disposable evidence is a tested pairing, not a new runtime
version pin. Existing Core and provider authority must still be admitted.

The implementation retains complete source tests and 296 executed checks in the
pinned disposable Core lane (289 distinct cases, seven repeated entry controls).
Synthetic entities and fake cover/notification services do not prove household
behavior. Final clean-candidate Full/Evidence, exact-head CI and bounded release
delta review are required independently of those retained results.

Publication, installed image binding and the
[beta.16 acceptance contract](V2_4_0_BETA16_ACCEPTANCE.md) are separate stages.
Deployment needs its own authority. A prior Engineering image is not a rollback
of household configuration: preserve durable records and separately review any
downgrade, particularly after a marked plan exists. No garage configuration,
script, automation, cover action or recovery operation is authorized by these
release notes.
